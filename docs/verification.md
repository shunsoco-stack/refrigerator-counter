## 1. 静的検査・単体テスト・本番ビルド

プロジェクトのルートで、Node.js 24.x を使って実行します。

```sh
npm ci
npm run lint
npm run typecheck
npm run test
npm run build
```

`npm run verify` は依存関係のインストールを除く上記 4 つの検証を順番に実行します。最終コミットに対する終了コードと件数を記録してください。

単体テストでは、保存データの検証、重複 ID、不正日時、日付境界、月曜始まり・年越しの週、Undo の一段階制約、実績の永久保持、CSV の BOM・引用符・数式対策、経過時間、メッセージの巡回を確認します。既存の 79 件成功という担当者報告と、最終統合版の検証結果は別に記録します。

## 2. ブラウザでの検証

必要に応じて `npx playwright install chromium` でテスト用ブラウザを準備し、`npm run test:e2e` を実行します。`BASE_URL` 未指定時の対象は `http://localhost:3000` です。公開 URL を使う場合は `BASE_URL` に明示します。オフラインは開発サーバーではなく、`npm run build` 後の本番サーバーまたは公開アプリで確認してください。

実利用者の保存データを操作せず、検証専用の新しいブラウザコンテキストを使います。

| 観点 | 確認内容 |
| --- | --- |
| 初期表示 | 今日・今週・累計が 0、理由は「なんとなく」、最終時刻と経過時間が未記録表示 |
| 記録 | 押すたびに 1 件だけ増え、理由・時刻・メッセージが更新される |
| 理由 | 5 種類すべてを選択でき、変更は次の記録だけに適用される |
| 永続化 | 再読み込み後も記録、選択理由、実績、直前の Undo 対象を保持する |
| Undo | 最新 1 件のみ戻せる。連続した取り消しはできず、新規記録後には再び 1 件戻せる |
| 実績 | 同じ日の 10 / 30 / 50 回で解除され、翌日や Undo 後も残る |
| 日付・週 | 日付変更後も履歴を保持し、今日の表示は新しい日へ切り替わる。週は月曜開始 |
| グラフ | 時間帯別は今日の 24 時間、週間は月曜から日曜の 7 日を表示。数値が集計と一致する |
| テーマ | ライト・ダーク・システム設定が機能し、再読み込み後も選択を保持する |
| CSV | ダウンロードした CSV の件数、順序、日本語、BOM、日時、理由が一致する |
| 共有 | OS 共有、コピー、手動テキストの分岐とキャンセル時の動作を確認する |
| 保存失敗 | 保存不可・容量超過時に増えたように見せず、不正データを自動上書きしない |
| アクセシビリティ | キーボード操作、ダイアログの開閉、フォーカス、読み上げラベル、動きを減らす設定を確認する |
| レイアウト | モバイル・デスクトップで横はみ出し、文字の欠け、重なりがない |

ブラウザごとのネイティブ共有・インストール UI の差は許容し、フォールバックが使えることを確認します。ひとつの Chromium テストで全 OS・ブラウザへの対応確認が済んだとは扱いません。

## 3. PWA・オフライン

1. 安全なコンテキストの本番アプリを、新しい検証用ブラウザでオンライン表示する。
2. Service Worker の登録・インストール・制御が完了し、アプリの HTML、必要な JS / CSS、manifest、アイコンが保存されたことを確認する。
3. オンライン中に記録し、ブラウザをオフラインにして再読み込みする。
4. 画面と既存の記録が復元され、オフラインの新規記録・Undo・CSV が動作することを確認する。
5. オンラインへ戻して再読み込みし、オフラインで追加した記録も残っていることを確認する。
6. キャッシュの更新が記録の localStorage や別アプリのキャッシュを削除しないことを確認する。
7. manifest、favicon、Apple 用アイコン、通常・maskable アイコン、OG 画像のレスポンスを確認する。

初回アクセス前からオフライン、キャッシュ削除後、OS による保存領域回収後の起動は対象外です。RSC・API・Analytics・外部通信をキャッシュしないことも確認します。Service Worker の更新直後と、実際に端末へインストールした場合の確認結果は別途記録してください。

## 4. Secret Scan

PATH 上に Gitleaks を準備するか、`GITLEAKS_BIN` に実行ファイルのパスを指定して `npm run secret:scan` を実行します。スクリプトは `dir` と `git` の検査を行います。ソース、公開するファイル、コミット済み履歴の対象をそれぞれ記録してください。`.env`、デプロイ認証情報、トークン、個人データが公開対象にないことも確認します。依存パッケージの脆弱性検査と Secret Scan は別の検証です。

作業環境内には `.portfolio-audit/tools/gitleaks-8.30.0/gitleaks.exe` があり、読み取り専用の `version` と `dir --help` でバージョン 8.30.0 の起動を確認しています。このパスは親ワークスペースにあり、リポジトリに同梱するツールではありません。Gitleaks の起動確認はスキャン実施・検出なしの証明ではありません。

検出内容をログへ出す場合は秘密値を伏せます。既存の別プロジェクト向け設定や広範な除外をそのまま流用せず、除外理由と走査対象を記録してください。検出があれば原因を調べ、必要ならキーの失効・再発行を行い、再走査します。

### Analytics のプラン制約

カスタムイベントには Vercel Pro / Enterprise が必要です。Hobby のページ閲覧計測と混同しません。アプリには 8 種類のイベント呼び出しを実装していますが、SDK が呼ばれたこと、リクエストを送ったこと、ダッシュボードに集計されたことを区別して確認します。[Vercel 公式のプラン条件](https://vercel.com/docs/analytics/limits-and-pricing)

プラン条件を満たさない場合は「コード実装済み・本番のカスタムイベント計測は未確認 / 利用不可」と記録します。ユーザーの明示的な許可なく、有料プランへの変更、トライアル開始、有料アドオン追加をしません。ページ閲覧とイベントの記録が匿名の集計であること、記録 ID・全履歴・保存された開閉日時をアプリのカスタムプロパティへ含めないことも確認します。[Vercel のプライバシー説明](https://vercel.com/docs/analytics/privacy-policy)
